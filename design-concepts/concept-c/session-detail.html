AI summary

scan-corp.io exposes a legacy administrative panel at /admin-legacy with no authentication in front of it, reachable directly from the public internet. Combined with an end-of-life OpenSSH build on the same host, this is enough for an attacker to move from reconnaissance to full configuration access without needing a single credential. Two lower-severity findings — a cookie missing security flags and a leaked server banner — make follow-on attacks easier but are not the primary concern here. Remediation of the admin panel exposure should be treated as immediate.

Session Assistant

What does the OpenSSH vulnerability actually mean for us?

CVE-2016-6210 in OpenSSH 7.2 lets an attacker measure response timing to work out which usernames exist on the host. On its own that's just enumeration — but chained with the unauthenticated /admin-legacy panel, it hands an attacker a list of real accounts to target next.

Should we prioritize that over the other findings?

Fix the admin panel exposure first — it's the direct path to full config access with zero credentials. Patch OpenSSH alongside it, since it mainly matters as a way to strengthen that same attack chain.
